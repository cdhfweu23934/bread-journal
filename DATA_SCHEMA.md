`data/trades.json` is the only public data artifact. `tools/export-paper-data.mjs` reads retained local paper snapshots, bounded archived execution/event logs, the existing legacy market-cap cache, and the separate per-call USD conversion cache. It performs no network requests, provider reads, credential/config reads, Discord notifications, signing, Git operation, or deployment. Missing evidence stays `null`. It never changes the bot or its financial history.

Run once with `node tools/export-paper-data.mjs --source-root ../iJustNeedBreadFFS`, or use `--watch` for a serial local refresh every ten seconds. Import callers may use `exportPaperData({workspaceRoot, outputPath})`, with output restricted to this site's `data/trades.json`. The exporter writes a temporary file in the site's own `data` directory, fsyncs it, and atomically renames it to `trades.json`. Byte-identical output and timestamp-only heartbeat changes are skipped. `updatedAt` and `live.asOf` use the retained snapshot's `updatedAt` if supplied, otherwise the source file timestamp; they are not newly invented trade times. Publication remains a separate workflow.

Version 1 has exactly these fields:

- `schemaVersion`: `1`.
- `updatedAt`: UTC timestamp of the source snapshot.
- `versions`: `{version, registeredAt, summary, active}` rows from the local version registry. Only version, registration date, bounded summary, and whether it is the latest release are public. Behavior fingerprints and paths are excluded.
- `live`: `{state, asOf, botVersion, closed, unresolved, open}`. State is `running`, `stopped`, `awaiting_recovery`, or `unknown`. `botVersion` prefers the snapshot's own version/behavior stamp when it matches a registered release, so registering a later release cannot relabel a still-running older process. A stopped legacy snapshot falls back to the current registered release; an active unstamped process remains null. `versions[].active` identifies the latest registered release separately. Unresolved inventory remains distinct from closed inventory.
- `stats`: `{closedTrades, writtenOffTrades, scoredTrades, unresolvedTrades, openTrades, knownPnlTrades, wins, losses, winRatePercent, meanPnlPercent, meanScorePercent, lastTenCappedMeanPercent}`. Sold-trade PnL statistics remain separate from scoring outcomes. `meanScorePercent` and the last-ten capped score include explicit written-off losses.
- `trades`: rows `{id, mint, name, symbol, botVersion, status, entryMarketCapUsd, exitMarketCapUsd, pnlPercent, scorePercent, openedAt, closedAt}`. Status is `closed`, `open`, `unresolved`, or `written_off`. A version is emitted only from a position's own immutable stamp matching its registered behavior; legacy trades remain `botVersion:null` (Before versioning). The current thirteen legacy trades are not relabeled 1.0.0. These additive fields retain schema version 1; viewers should tolerate missing version/score fields in older payloads.

A `written_off` row requires the explicit paper policy proof and its matching distinct archived `paper.writeoff` event. It is not a sale: `pnlPercent`, `exitMarketCapUsd`, and `closedAt` remain null. Its `scorePercent` is −100 by the written requirements, with no invented proceeds or discarded inventory. Actual sold rows keep `scorePercent` equal to their exact executed-price PnL; aggregate scoring caps positive contributions at +333%. Unknown/open rows remain unscored. Future recovery is a separate actual-receipt record and cannot erase the original write-off score.

Trade PnL preserves the existing report definition exactly: `(actual executed gross exit proceeds − actual executed entry principal) / actual executed entry principal × 100`. It derives from matching successful local VM buy/sell facts, not the position's rounded stored ROI, wallet cash outlay, refundable rent, or a quote. Fees are excluded from this metric. All losses remain in the series. The last-ten scoring mean requires ten terminal outcomes (actual sales or validated write-offs), and caps only each positive contribution above +333%. Open and unresolved rows have no realized PnL or exit market cap.

Market cap uses actual executed principal or gross proceeds divided by actual token quantity, multiplied by the position's recorded display supply. Legacy positions without nominal-supply markers retain actual mint supply from decoded execution facts, a strictly matching cache, or matching execution mint-account bytes. New Mayhem positions with complete immutable entry mode and nominal-supply markers use the fixed nominal 1,000,000,000-token curve supply for both entry and exit display. Partial or malformed markers produce unknown market caps; no historical mode or supply basis is backfilled. This executed-average-price display convention is not canonical marginal spot market cap or an exact Axiom reported value. Actual mint supply used for protocol fees, token accounting and PnL remains unchanged. USD conversion reuses the position's already cached display-time SOL/USD observation, not a historical USD execution price; no fresh rate is fetched, entry and exit share that cached rate, and unavailable USD values remain `null`.

Entry/exit timestamps come only from matching archived `paper.entry` and `paper.exit` records. Original process monotonic times are never converted to UTC or relabeled. The current retained trade records do not prove token names/symbols, so those fields remain `null`; UI may display a shortened mint. Such metadata must not be inferred from news or unverified labels.

The explicit `paper_calls` mode with model `delayed_live_market_cap_calls_v1` is also accepted. Its new call rows retain `entryMarketCapSol`, `exitMarketCapSol` and `pnlBasis: "delayed_market_cap_change"`. They also expose entryUsdConversion and exitUsdConversion (null or {source, minuteStartMs, solUsd}) for display provenance. Their PnL is recomputed from the exact retained entry/exit market-cap fractions; it does not require or claim wallet settlement. Call times use the retained UTC observation timestamps. Open calls have no exit cap or realized return. The same positive-only +333% scoring cap and all losses apply. Legacy position export and write-off proof rules remain unchanged.

Call USD market caps multiply each exact native-lamport market-cap fraction by its own cached SOL/USD decimal rate. The cache must match paperPositionId, mint, that side's exact MarketCap.observedAtMs, and its containing UTC minute. The rate source is coinbase_SOL_USD_1m_close: the close/as-observed close of the recorded minute, not an exact-millisecond execution rate. Entry and exit may use different rates. Missing or mismatched conversions leave USD caps null; the UI shows an em dash and never falls back to SOL. The drawer identifies the conversion minute. Existing SOL fields remain for JSON compatibility, without display. FX affects display only: PnL and scoring continue to use the original native market-cap fractions. Legacy USD conversion and all historical returns remain unchanged.

The public allowlist excludes wallet addresses, account arrays, raw receipts, execution IDs, source paths, private provider details, keys, webhooks, configuration, and debug/error payloads. `assertPublicSchema` rejects extra keys before any output write. A browser-side `123` gate is a convenience screen; static public JSON remains publicly retrievable and contains only this sanitized projection.

USDC paper calls expose `quoteCurrency: "USDC"` and omit the SOL cap fields. PnL and scoring use the exact `marketCapQuoteAtomic` entry/exit fractions only when both sides have matching USDC identities. USD display additionally requires a retained `marketCapUsd` fraction equal to quote-atomic cap ? the actual recorded USDC/USD rate ? 1,000,000. The rate source is `coinbase_USDC_USD_exchange_rate`; its request must precede receipt, receipt must precede the cap observation, and receipt age must be at most60 seconds. Public conversion metadata contains only `{source, observedAtMs}` for that received rate. Missing or invalid FX leaves USD unknown without changing PnL; no USDC peg is assumed. SOL candle enrichment skips USDC observations. All legacy output and conversion formats remain supported.
